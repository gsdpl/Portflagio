6. SYSTEME DE PROJETS (AJOUT / MODIFICATION)
================================================================================

Pour ajouter un nouveau projet, 5 etapes :

ETAPE 1 — Assets dans public/projects/{slug}/
  - thumbnail.png ou .svg (logo du projet, ~2880x1800 ou 2880x1620)
  - 3 screenshots (gallery) en .png ou .webp avec dimensions exactes
  - (optionnel) public/projects/scenes/{slug}.png pour l'Ink Transition

ETAPE 2 — Entree dans src/data/projects.ts
  Ajouter un objet ProjectMetadata dans le tableau `projects` :
  {
    slug: "mon-projet",
    year: 2025,
    technologies: ["Tech1", "Tech2"],
    categories: ["development", "design", "product"],  // 1 a 3
    accent: "#hexcolor",
    accentSoft: "#hexcolor-dark",
    thumbnail: { src: "/projects/mon-projet/thumbnail.png", width: W, height: H },
    gallery: [
      { src: "/projects/mon-projet/screen1.png", width: W, height: H },
      ...
    ],
    externalUrl: "https://..." // optionnel
  }

  IMPORTANT : l'ORDRE dans le tableau = l'ordre d'affichage sur la grille.

ETAPE 3 — Couleur de broderie dans src/lib/threads.ts
  Ajouter la couleur (hex) dans le tableau `threads`, A LA MEME POSITION
  que le projet dans data/projects.ts. L'index doit correspondre.
  Les filtres SVG sont generes dynamiquement (embroidery-N, logo-N).

ETAPE 4 — Contenu MDX
  Creer content/projects/{slug}/fr.mdx et en.mdx avec :
  ---
  title: "Nom du Projet"
  summary: "Description courte"
  kicker: "Categorie · Sous-categorie"
  galleryAlt:
    - "Alt text image 1"
    - "Alt text image 2"
    - "Alt text image 3"
  ---
  ## Titre principal
  Contenu libre en MDX...

ETAPE 5 — Verification
  - npm run build (doit compiler sans erreur)
  - npm run dev -> verifier sur localhost:3000
  - Verifier la carte sur la grille (logo, hover -> screenshots)
  - Verifier la page projet (/en/projects/{slug})
  - Verifier l'Ink Transition si scene ajoutee

7. SYSTEME DE FILTRES SVG (BRODERIE)
================================================================================

Definis dans : src/components/glass/glass-filter-defs.tsx
Couleurs dans : src/lib/threads.ts

Deux types de filtres par projet, generes dynamiquement :

1. embroidery-N : duotone broderie
   - Desature -> niveaux -> duotone (cloth blanc + couleur thread)
   - Turbulence pour effet de couture
   - Utilise sur les logos dans la grille (.card-thumb-logo)
   - Utilise en tapisserie sur les pages projets (::before avec opacity 6%)

2. logo-N : duotone inverse pour miniatures
   - Le fond devient la couleur du projet
   - Le logo devient blanc
   - Pas de displacement (reste net)
   - Utilise sur les miniatures de cartes

CSS custom properties par carte (dans project-grid.tsx) :
  --thread-color  : couleur du thread (hex)
  --thumb-filter  : url(#embroidery-N)
  --logo-filter   : url(#logo-N)
  --card-thumb    : url(/projects/{slug}/thumbnail.ext)

9. FEATURE : SMASH GAME ("Destroy the AI Portfolio")
================================================================================

Concept : un faux portfolio IA generique recouvre le vrai portfolio.
L'utilisateur attrape un marteau et casse le faux pour reveler le vrai.

Fichiers : src/components/smash-game/

PHASES (state machine dans smash-game-provider.tsx) :
  dormant  -> localStorage dit "deja joue", modale rejouer/skip
  active   -> Premier visit, faux portfolio visible, bouton marteau pulsant
  playing  -> Timer demarre, destruction active, HUD visible
  complete -> 100% detruit, ecran de resultats
  dismissed -> Overlay retire, vrai portfolio accessible

MECANISME :
  - Canvas offscreen sert de masque CSS (mask-image) sur le faux portfolio
  - Canvas blanc = faux visible. On peint en noir (destination-out) = trous
  - document.elementFromPoint() pour detecter les elements touches
  - Effects canvas pour les particules d'eclats

SCORING :
  - Interactif (CTA/bouton) : 100 pts
  - Carte/panel : 75 pts
  - Titre (h1/h2) : 50 pts
  - Texte : 25 pts
  - Vide : 10 pts
  - Combo : hits < 800ms, multiplicateur max 4x
  - Auto-complete a 95%

RANGS (par temps) :
  < 30s : Artisan du Moyen Age
  < 45s : Chevalier du Pixel
  < 60s : Ecuyer Destructeur
  < 90s : Paysan du Pixel
  90s+  : Touriste

Z-INDEX :
  z-9000 : smash-overlay (faux portfolio + canvas)
  z-9010 : HUD (barre, timer, combo, bouton)
  z-9999 : Ink Transition (existante)

CSS : ~400 lignes a la fin de globals.css
  - .smash-overlay, .fake-portfolio (Inter, gradients bleu-violet)
  - .smash-hud, .smash-end
  - .smash-hit-layer avec curseur marteau SVG inline

ACCESSIBILITE :
  - prefers-reduced-motion: reduce -> skip direct
  - Skip button toujours visible (min 44x44px)
  - aria-hidden="true" sur l'overlay

10. TRANSITIONS DE PAGE (INK TRANSITION)
================================================================================

Quand on clique sur un projet, une animation d'encre recouvre l'ecran :
  1. L'image de scene (public/projects/scenes/{slug}.png) se deploie
  2. Le titre du projet apparait lettre par lettre en Grenze Gotisch
  3. La page projet se charge derriere
  4. L'encre se retire

Phases : idle -> in -> hold -> out
Durees : IN=950ms, OUT=480ms, LETTER_BASE=450ms, LETTER_STEP=62ms

Le composant TransitionProvider enveloppe les children dans layout.tsx.
Navigation declenchee via useInkTransition() hook.

15. PIEGES CONNUS
================================================================================

1. CACHE TURBOPACK : apres des gros changements CSS, Turbopack peut
   corrompre son cache et renvoyer des erreurs 500 "Cannot find module
   turbopack_runtime.js". Solution : taskkill node.exe + rm -rf .next

2. ORDRE THREADS/PROJECTS : le tableau `threads` dans lib/threads.ts DOIT
   etre dans le meme ordre que le tableau `projects` dans data/projects.ts.
   Sinon les couleurs de broderie seront decalees.

3. MOTION V12 : s'importe depuis "motion/react", PAS "framer-motion".
   AnimatePresence, motion.div, useAnimate, etc. = "motion/react"

4. EMBROIDERY FILTER SUR SCREENSHOTS : le filtre de broderie ne doit
   s'appliquer QU'AU LOGO (.card-thumb-logo), pas aux screenshots du
   carousel. Le CSS utilise .project-card-media img.card-thumb-logo
   pour cibler uniquement le logo.

5. HOVER CARTE : le hover doit etre detecte sur toute la carte
   (article.project-card), pas seulement sur la zone media. Le state
   hoveredSlug est gere au niveau du ProjectGrid.

6. TAPISSERIE : supprimee des cartes (display: none sur .project-card::after),
   presente sur les pages projet (::before avec --thumb-filter a 6% opacity).

7. FAUX PORTFOLIO SCROLL : le .smash-hit-layer (z-index 2) bloque le
   scroll en phase "active". Il n'est rendu QUE quand phase === "playing".

8. PLAYWRIGHT : utilise Edge, pas un Chromium telecharge. Le chemin est
   code en dur dans verify-ui.mjs.
